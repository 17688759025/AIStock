# AIStock

实时页面入口为 `bid-compass.html`，尾盘狙击历史入口为 `close-history.html`，两页可以互相跳转。

## 竞价结果

GitHub Actions 从北京时间工作日 04:45 起设置多个唤醒时点（同一任务串行执行），第一个成功启动的进程等待至 09:25:03。提前唤醒用于容忍免费 cron 数小时级延迟。

1. 在 09:25～09:30 连续竞价开始前读取完整市场，校验行情日期和采集时间。新浪优先，东方财富备用；不使用延迟行情节点补竞价原始报价。
2. 使用页面内的同一套评分函数，固定昨日历史因子、主板/全部市场各自的 Top 5，以及盘前事件确认的 1 只或 0 只结果。因子缺失会按已有降级规则处理，并随结果一起冻结，不再在浏览器补齐后改排名。
3. 一次性写入 `data/auction/YYYY-MM-DD.result.json`。含原始候选因子、评分、采集时间、版本和快照标识；已存在的日期文件不能覆盖。
4. 页面读取该日期文件，按原顺序展示。刷新仅请求已入选股票的实时涨跌，失败时保留已有值。09:30 后仍缺正式文件时，网页可利用行情中的“今日开盘价”重建竞价涨幅，按现有模型在当前浏览器计算一次并冻结；正式文件稍后出现时自动优先。

GitHub 定时任务不是准点服务，数据接口也可能失败。若任务未在截止前完成，当日无正式结果；第二次任务只能在时间窗口内补采，不能盘后补写。网页降级重建不伪装成正式快照：竞价价可以从今日开盘价可靠还原，但盘中累计成交量、成交额和盘前单只观察的量能确认不能还原为 09:25 状态，因此会明确标记“本机重建”，不写入仓库、不跨浏览器共享、不进入历史胜率。行情日期或全市场覆盖无法确认时不会缓存空结果，下次刷新仍可重试。`--debug` 仅输出 `/tmp/auction-result-debug.json`，不会提交为正式数据。

08:50 盘前池必须在 09:25 前生成。缺失时，单只观察结果冻结为空；不影响竞价 Top 5。

盘前任务从北京时间工作日 04:35 起尝试唤醒，另设 06:35、08:35 备用时点，进程等待到 08:50 采集。采集开始和写入前均检查 09:25 截止时间，迟到任务明确失败，不发布下午数据。昨日涨停池以指数日线确定上一实际交易日，校验返回日期；公告排除采集时点之后的内容。日期文件存在时保留原文件。浏览器读取当日日期文件并校验生成时间；数据缺失会显示“数据未就绪”，与正常筛选后的 0 只区分。提前唤醒仍不能保证 GitHub 准点调度。

## 盘中交易窗口

昨日涨停接口若忽略请求日期、返回当天池或请求失败，会标记该因子缺失并使用公告候选继续筛选，不把当天涨停池作为昨日数据。公告读取失败仍视为采集失败，避免漏掉负面公告后发布候选。

每次刷新固定一个北京时间窗口，分时、异动和指数趋势使用相同窗口。午休不计入交易分钟。

| 刷新时刻 | 使用区间 |
| --- | --- |
| 09:35 | 09:30～09:35（5 分钟） |
| 10:00 | 09:30～10:00（30 分钟） |
| 11:34（午休） | 11:00～11:30（30 分钟） |
| 12:59（午休） | 11:00～11:30（30 分钟） |
| 13:00 | 11:00～11:30（30 分钟） |
| 13:05 | 11:05～11:30 + 13:00～13:05（30 分钟） |
| 13:30 | 13:00～13:30（30 分钟） |
| 15:00 以后 | 14:30～15:00（30 分钟） |

交易时段内以当前分钟为终点；午休时以当日 11:30 为终点，收盘后以当日 15:00 为终点。只读取当前北京时间日期的分时，不能用上一交易日补足；当日分时不足或陈旧时直接判定无效。三个板块中，只有盘中半点推票会随刷新重新选票。

## 尾盘冻结结果

GitHub Actions 从北京时间工作日 08:45 起设置多个唤醒时点；第一个成功启动的任务持续等待至 14:30:03 开始采集。这样可以容忍免费定时任务数小时级的调度延迟，且无需有人打开网页。并发组保证同一时间只有一个正式采集任务运行。

1. 在 **14:30 当分钟（14:31 前）**读取资金流 Top 200、涨速 Top 100，以及 14:00:00～14:30:00 的看多异动。异动分页追溯到窗口起点、去重，不只取不断滚动的最新 500 条；不完整的异动响应标为缺失，不用截断数据冒充完整数据。
2. 对候选补取同一采集分钟的报价、主力净流入和净占比，检查日期、时点和覆盖率。主力资金仍是**截至采集时的当日累计值**，不是 14:00～14:30 的净流入差额。公开接口不是原子快照，因此记录并展示真实的采集起止秒数，不声称全部字段同时发生于 14:30:00。
3. 分时可以稍后读取，但价格、趋势和区间量能只使用截至 14:30 的数据。沿用原有尾盘资金模型及权重，冻结主板/全部市场各自最多 5 只的名单、全部评分输入和排序；评分不要求全天红盘。资金和异动等缺失情况写入 `sourceCoverage`。
4. 14:35 前完成计算，一次性保存 `data/close/YYYY-MM-DD.result.json`；已存在的日期文件不能覆盖。页面优先读取 GitHub 原始文件，也可读取 Pages 副本，两者对应同一份结果。正式文件存在时，首次在 14:50 打开、换浏览器、切换板块、再次刷新，都不重新筛选。
5. **只有“实时涨跌”列继续刷新**，不会反过来影响冻结名单、资金、评分和排序。实时接口失败时保留已有值；即使入选股票后来涨停，也不从已经冻结的历史名单中删除。未入选时的涨停剔除规则不变。

正式快照同时更新 `data/close/index.json`，供历史页面发现各日期文件。快照里的 `snapshotPrice` 和 `snapshotChange` 分别保存 14:30 实采价格与当时涨幅；旧文件缺少价格时，历史页和结算脚本可用“前收 ×（1 + 当时涨幅）”还原。

另一个 GitHub Actions 在北京时间工作日 15:10 运行 `scripts/update_close_history.cjs`。它对尚未结算的快照查找市场的下一实际交易日（自动跨周末、节假日），读取该日收盘后确定的未复权最高价，并一次性写入不可覆盖的 `data/close-history/YYYY-MM-DD.json`。日线使用东方财富，失败时切换腾讯，并在个股记录里保存实际来源。收益口径固定为 `下一交易日最高价 / 14:30快照价 - 1`；停牌或个股日线缺失会标记为未取得，不计入汇总比例。`data/close-history/index.json` 只负责日期发现。

采集任务即使提前启动也不会提前取数；仍然只允许 14:30:00～14:30:59 的报价。若所有唤醒任务都在 14:31 后才启动、报价覆盖不足或分时全部失败，Actions 不生成伪造的正式结果，也不在 14:50 补采并标成 14:30。14:35 前网页仅提示结果尚在发布；14:35 后仍无正式文件时，用户刷新会按同一尾盘模型现场补算一次，并按日期和“仅主板/全部市场”缓存在当前浏览器。补算仍严格使用 14:00～14:30 分时，但主力资金、涨速及候选排行只能取补算时接口返回的累计状态，因此显著标记“本机补算”，不会写入仓库、不会跨浏览器共享、不会进入尾盘历史胜率。当天后续刷新固定本机名单，只更新实时涨跌；若正式文件稍后发布，则正式结果自动优先。有效数据筛选后确实无达标股票，会缓存并显示“本机补算无达标股票”，避免每次刷新反复改名单。任务完成、推送和 Pages 部署需要时间，GitHub 定时任务仍不提供准点保证。`--debug` 只输出 `/tmp/close-result-debug.json`，不能作为正式快照使用。

```sh
node --test tests/*.test.cjs

node --check scripts/collect_close_result.cjs
node --check scripts/update_close_history.cjs
```
