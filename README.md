# AIStock

页面入口为 `bid-compass.html`。

## 竞价结果

GitHub Actions 在北京时间工作日 09:05、09:15 尝试唤起采集任务（同一任务串行执行），进程等待至 09:25:03。

1. 在 09:25～09:30 连续竞价开始前读取完整市场，校验行情日期和采集时间。新浪优先，东方财富备用；不使用延迟行情节点补竞价原始报价。
2. 使用页面内的同一套评分函数，固定昨日历史因子、主板/全部市场各自的 Top 5，以及盘前事件确认的 1 只或 0 只结果。因子缺失会按已有降级规则处理，并随结果一起冻结，不再在浏览器补齐后改排名。
3. 一次性写入 `data/auction/YYYY-MM-DD.result.json`。含原始候选因子、评分、采集时间、版本和快照标识；已存在的日期文件不能覆盖。
4. 页面读取该日期文件，按原顺序展示。刷新仅请求已入选股票的实时涨跌。实时请求失败时保留已有值；缺少当日正式文件时明确提示缺失，不用盘中数据重建竞价结果。浏览器旧版的 09:25～09:35 缓存不再使用。

GitHub 定时任务不是准点服务，数据接口也可能失败。若任务未在截止前完成，当日无正式结果；第二次任务只能在时间窗口内补采，不能盘后补写。`--debug` 仅输出 `/tmp/auction-result-debug.json`，不会提交为正式数据。

08:50 盘前池必须在 09:25 前生成。缺失时，单只观察结果冻结为空；不影响竞价 Top 5。

## 盘中交易窗口

每次刷新固定一个北京时间窗口，分时、异动和指数趋势使用相同窗口。午休不计入交易分钟。

| 刷新时刻 | 使用区间 |
| --- | --- |
| 09:35 | 09:30～09:35（5 分钟） |
| 10:00 | 09:30～10:00（30 分钟） |
| 13:00 | 11:00～11:30（30 分钟） |
| 13:05 | 11:05～11:30 + 13:00～13:05（30 分钟） |
| 13:30 | 13:00～13:30（30 分钟） |

分时不足或陈旧时，不把缺口当午休拼接。尾盘仍使用 14:00～14:30 独立资金模型。
